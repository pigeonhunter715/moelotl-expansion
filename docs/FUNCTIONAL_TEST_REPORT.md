# 游戏内功能测试记录 · 2026-11-19

环境：隔离 RimWorld 1.6.4871 rev591，Harmony、HAR、CQF、萌螈本体、螈僵扩展、本扩展和独立测试模组。实际通过游戏生成地图、正常tick、原版JobDriver、原模组武器和世界商队执行；没有使用玩家正式存档。

启动命令：`./tools/runtime-smoke.ps1 -Functional`。测试源码为 `Tests/RuntimeFunctional.cs`；最终 `FUNCTIONAL_COMPLETE checks=50`，包含四柱通天仪的真实丹炉进度与单批燃料检查。本体冒烟回归使用不带该参数的启动命令。

最终功能轮次：`FUNCTIONAL_COMPLETE checks=50`；引擎日志未发现未处理异常或XML错误，进程正常退出。随后原有回归通过 `COMPLETE checks=72`，同样正常退出。加载仍有已有的翻译和数值解析提示，不称为零警告。

## 修复

`TryTakeOrderedJob` 会给任何玩家下达的工作设置 `playerForced=true`。旧代码以该标记区分“手动装一枚”和“补至目标”，导致玩家下达的目标补货可能在目标下调后仍按旧数量交付。

现使用独立、可存档的 `MX_LoadPendantOne` JobDef 表达“装一枚”；`MX_RestockPendant` 无论是否玩家强制，都在取药和交付时重读当前目标，并服从补货开关。两类工作共同参与重复搬运检查。旧存档里的普通补货工作也会遵守目标；旧版尚未结束的“装一枚”工作保守按目标补货处理，可重新点一次装药。

冒烟回归还发现安魂递送被跳跃中断：取消时 `Available=false`，角色实际位于本体的 `AxolotlPawnMoveFlyer` 内。原判断只允许地图角色或商队，漏掉了跳跃时暂时离图的角色。现增加严格条件：直接容器是仍在地图上的 `PawnFlyer`，且 `FlyingPawn` 就是佩戴者。普通离图、其他收容、死亡和卸下仍按原条件停止。新增确定性场景使用原生跳跃容器，仅延长该次测试飞行至240 ticks，保证递送在空中到期。

## 测试条件与范围

- 初次随机地图包含不可行走地形，取药未能完成；测试区随后改为普通土地。此为测试装置修正。
- 普通喂药要求持续接触，目标自行走开会中断；正常完成场景让目标等待，中断场景单独取消工作验证。
- 螈僵测试目标免日晒以隔离环境伤害；攻击使用原生命、命中、伤害、耗气和弹丸流程，未强制把命中改成成功。
- 移除测试装置曾铺设的无支撑屋顶，避免塌顶引入额外环境干扰；功能测试区保持普通土地。跳跃取消问题以容器日志确证，不能只归因于屋顶或等待时间。
- 这次证明了两种指定武器和这些具体操作，不证明所有第三方技能、所有弹丸、飞僵、多目标攻击或所有运输方式都已覆盖。
- 四炉360天离散批次模型及单批燃料边界已有专项记录，但它不模拟真实殖民地种植、搬运和停工；交易经济、完整培养／修脉、弹丸跨存档与多模组组合仍需独立验收。

实际运行次数、最终断言数量与回归结果见 `IMPLEMENTATION.md` 的本轮记录。诊断日志中出现过的安魂递送取消均由跳跃时的 `AxolotlPawnMoveFlyer` 所致，已通过确定性空中递送回归修复。
